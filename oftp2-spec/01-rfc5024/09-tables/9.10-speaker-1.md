# Table 9.10 — Speaker (partie 1)

> `RFCs/rfc5024.txt` §9.10 (l. ~4799)

## À quoi elle sert

Tant que votre entité est **Speaker** : envoyer fichiers, gérer crédit DATA, changer de tour (**CD**), envoyer **EERP/NERP**, libérer la session.

**Client ou serveur TCP** : indifférent — seul le rôle **Speaker** compte.

## États (colonnes)

> Tous ces états = entité **Speaker** (émetteur du fichier). **TCP typique** : C ou S selon le tour, pas selon la table.

| État | Entité | TCP typique | Description |
|------|--------|-------------|-------------|
| `IDLESP` | **Speaker** | C ou S | Au repos, peut lancer un fichier |
| `IDLESPCD` | **Speaker** | C ou S | `F_CD_IND` émis, CD pas encore sur le fil |
| `WF_RTR` | **Speaker** | C ou S | EERP/NERP envoyé, attend **RTR** |
| `WF_CD` | Speaker (attente tour) | C ou S | Listener a demandé CD via EFPA |
| `OPOP` | **Speaker** | C ou S | **SFID** envoyé, attend SFPA/SFNA |
| `OPO` | **Speaker** | C ou S | Transfert sortant actif |
| `OPOWFC` | **Speaker** | C ou S | Crédit épuisé, attend **CDT** |
| `SFSTWFCD` | **Speaker** (buffer) | C ou S | `F_START_FILE_RQ` stocké |
| `ERSTWFCD` | **Speaker** (buffer) | C ou S | `F_EERP_RQ` stocké |

## §9.10.3 — Prédicats et actions

RFC intégral : [[00-actions-et-predicats#Table 9.10 — Speaker 1]].

### Prédicats (P1–P5)

| P | Signification |
|---|---------------|
| P1 | Restart interdit ou `V.Mode = Receiver-only` |
| P2 | `SFPA.pos > SFID.pos` (erreur protocole) |
| P3 | `Credit_S - 1 = 0` |
| P4 | Pas de special logic |
| P5 | EERP/NERP signé demandé |

### Actions (1–18, locales à cette table)

| ID | Résumé |
|----|--------|
| 1–2 | Stop / start timer |
| 3–4, 9 | EERP (+ buffer `V.Req-buf`) |
| 5–6, 10 | SFID (+ buffer) |
| 7–8 | `F_START_FILE_CF` ± depuis SFPA/SFNA |
| 11 | Build exchange buffer (PDU) |
| 12–13 | `Credit_S = Window` / `Credit_S -= 1` |
| 14 | CRC + special logic (émission) |
| 15–17 | NERP (+ buffer) |
| 18 | Signature CMS EERP/NERP |

Ex. **K** (SFPA) : **1, 2, 7, 12** → `F_START_FILE_CF`, **OPO**.
